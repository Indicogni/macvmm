## Predict

- Commits to (a) or (b) before running, with a reason.
- Afterwards records what the run showed: an instruction abort at `pc=0x200`, not an alignment fault.
- If the guess was (a), names the belief behind it ("the hardware sends every guest exception to the VMM") and why it was wrong.

## Q1

- The VM exit was an instruction abort (class `0x20`) at PC `0x200`, a translation fault in stage 2: nothing is mapped at IPA `0x200`.
- The alignment fault never left the guest: an exception at EL1 is routed to EL1, so the CPU went to the guest's own vector table at `VBAR_EL1 + 0x200`. `VBAR_EL1` was 0, so the PC became `0x200`, and fetching from there is the second fault, the one routed to EL2 and forwarded to us.
- The first fault is in `ESR_EL1` (`0x96000021`: class `0x25`, a data abort at the same level; fault status `0x21`, alignment) and `ELR_EL1` (the address of the faulting load, `0x4008…`). `FAR_EL1` adds the unaligned address it used.
- States the rule: when the PC is a vector offset, `ELR_EL1` and `ESR_EL1` describe the exception the guest took before; here `ELR_EL1` points at the guest's code, not into the vector table, so it is the first fault (in the EL1t breakage it pointed into the table, and the first cause was gone).
- Common wrong answer: "we never got an exit" or "the hardware sends all exceptions to us". Nudge: which register would say where the first exception went?

## Q2

- Cites the section: at entry the MMU must be off, the instruction cache may be on or off, and the kernel image must have been cleaned to the point where all observers see the same memory.
- The kernel builds its own page tables and turns translation on itself, in an order it controls; it cannot know or trust the tables, translation state or cache contents a loader left behind.
- Gives one concrete failure: data the loader wrote may still sit in a cache while the kernel, running with caches off, reads stale bytes from memory; or a loader's translation would make the kernel's addresses mean something else.
- Connects it to our reset: clearing `SCTLR_EL1.M`, `C` and `I` is the VMM keeping that promise.
- Common wrong answer: "for speed". Nudge: what could the kernel read if the loader's cache lines were never written back?

## Q3

- The interrupt controller: HVF will not hand out a vCPU's redistributor until the VMM has written `MPIDR_EL1` (`hv_gic.h` says so; the slot follows creation order, not the value), and its own copy reads 0 until then; that is why the reference (which has the interrupt controller) failed with `HV_BAD_ARGUMENT` when the write was removed, while a one-CPU VMM without it showed no difference (chapter 12).
- The device tree: each CPU node under `/cpus` has `reg` equal to that CPU's MPIDR affinity bits, and the kernel matches it against what the CPU reports (chapter 10, chapter 20).
- PSCI `CPU_ON`: the kernel names the CPU to start by its MPIDR value, and the VMM must map it back to a vCPU (chapter 20).
- Concludes that the number must agree in all three places, or a CPU cannot be found, started or interrupted.
- Common wrong answer: "it is only an ID". Nudge: find who looks the ID up.

## Q4

- Defends each register with the question it answers, not as a list. Typical choices: `CPACR_EL1` (was floating point allowed, or did the fault come from a trapped floating-point instruction?), `MAIR_EL1` (which memory types were in force when translation was on?), `CNTV_CTL_EL0` and `CNTV_CVAL_EL0` (was the guest waiting for a timer?), `MDSCR_EL1` (was the guest single-stepping or debugging itself?), `TPIDR_EL1` (which task or CPU-local data was current?), and the instruction word at `ELR_EL1` (what did the first fault execute?).
- Recognises that the reference already prints the general-purpose registers, both stack pointers, `ELR_EL1`, `SPSR_EL1`, `ESR_EL1`, `FAR_EL1`, `VBAR_EL1`, `SCTLR_EL1`, `TCR_EL1` and the two `TTBR` registers, so each addition must answer a question those cannot.
- Notes that the dump must print only numbers and fixed names, never guest bytes as text.
- Common wrong answer: "everything". Nudge: which of these answers "what do I do next?"
