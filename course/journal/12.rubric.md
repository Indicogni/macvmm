## Q1

- Removed: the 10 VTIMER exits, the 10 WFI exits and the 10 canceled exits (the kicks chapter 11 used to re-check the timer line): three exits per tick, so the cost of the timer path and of idling is now zero exits.
- Left: the exits the guest's own devices cause. In the timer run that is one `hvc` per printed character (the debug hypercall); in the `irq` run, one data abort per UART register access. GIC register accesses and `ICC_*` system registers never exit.
- Host CPU for an idle guest stays near 1%, and the vCPU's time is reported as in-kernel WFI time.
- Given up: control. The timer, the wake-up and the delivery are the kernel's; no line of our code can see a tick, tighten a wake-up, or log an interrupt. Our runs did not show worse punctuality, so the honest claim is "less control", not "measurably later".

## Q2

- Breakage 1 (the device model never lowers its line): one keystroke started an endless stream of interrupts; the guest never reached its third keystroke or its final line, and millions of UART register accesses (data aborts) piled up until the timeout. The fault is the device model's: a level line must follow the device's state.
- The no-drain run (the guest never reads `DR`): about a million interrupts in one second for one character, and almost no VM exits, because the re-delivery happens entirely inside the kernel's GIC. The fault is the guest's: it never removed the cause.
- Explains the mechanism: a level interrupt stays pending while its line is high; if the line is still high when the EOI ends the active state, the interrupt is pending again at once.
- Contrasts with an edge line, which would give one interrupt per event and could not storm this way (but two edges that arrive before the first is acknowledged merge into one).

## Q3

- Matches jobs to blocks: the priority mask (`ICC_PMR_EL1`) is in the CPU interface; INTID 33's target is in the distributor (`GICD_IROUTER`, one per SPI); INTID 27 is a PPI, so its enable, priority and trigger live in that CPU's redistributor (`GICR_*`).
- The rule is in the header: after `hv_vm_create`, before any `hv_vcpu_create`. We saw `HV_NO_DEVICE` before the VM and `HV_BUSY` after a vCPU.
- Each vCPU gets per-CPU GIC state when it is created: its redistributor (the 128 KiB frame pair with its SGI and PPI configuration) and its CPU interface (`ICC_*` registers). The framework sizes and attaches those at vCPU creation, so the GIC must already exist.
- An error at set-up is better than a VM whose first vCPU has no CPU interface: the bug shows up at the line that caused it, not as a guest that never receives its timer.
- In the reference the rule is enforced by the types: the GIC is created inside the VM builder, before the `Vm` value that a `Vcpu` borrows exists.

## Q4

- Testing: the PL011's level rule (raise on input, drop on drain, drop on mask) is checked on any machine with `TestIrq` or a fake backend; no Hypervisor.framework, no signed binary, no Mac needed in CI.
- INTID numbering stays out of devices: the machine decides that the PL011 is INTID 33 and validates it once (`GicSpi::new` refuses non-SPIs and the MSI block); the device only says "high" or "low".
- The `unsafe` quarantine: only the `hvf` crate makes foreign calls; devices stay in safe code.
- The same device works with no controller (`NullIrq`, the chapter 11 mode) or a different one, and a failing `hv_gic_set_spi` is handled in one place (logged once, never fatal).

## Q5

- The stdin reader thread: it pushes the byte into the PL011 model, which recomputes its level and calls `hv_gic_set_spi(33, true)` through `GicSpi`; the header allows that call from any thread.
- The vCPU is not sleeping in our code any more: the kernel handled its WFI and parked it (our stats show zero WFI exits and seconds of in-kernel WFI time). The kernel's GIC knows an interrupt is now pending for that vCPU and resumes it there.
- In chapter 11 the vCPU slept on our condition variable, so we had to wake it; now the sleeper and the waker both live in the kernel, so no kick and no VM exit is involved.
- Notes what still needs a kick: stopping or pausing a vCPU from outside, for example to deliver a stop request or inspect it (chapter 20).
