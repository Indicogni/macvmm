# Course site design spec: "Build a VMM on Apple Silicon"

Target: `https://indicogni.com/build-your-own/vmm/`. Consistent with the existing indicogni landing site
(the `indicogni-site` repository): paper-and-ink palette, serif headings, system sans body, mono labels,
left-accent-bar cards, zero third-party anything.

Facts taken from the existing site (verified by reading it):
- Tokens in `public/style.css`: `--paper #FBF8F1`, `--ink #1E2227`, `--muted #5B616B`, `--rule #E4DDCC`,
  `--dot #E8E1D0`, `--card #FFFDF8`; dark: `#0E1116 / #E7E2D7 / #9AA0A8 / #262B33 / #1A1F26 / #141820`.
  Fonts: `--serif` Iowan/Palatino/Charter/Georgia, `--sans` system-ui, `--mono` ui-monospace/SF Mono/Menlo.
  Body 1.0625rem/1.6. Content wrap `max-width: 64rem`, `padding: 0 1.5rem`. Dotted paper background
  (`radial-gradient` 22px). Focus ring `2px solid var(--ink)`, offset 3px. Dark mode via `prefers-color-scheme` only.
- CSP in `public/_headers`: `default-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:;
  object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`. There is NO `script-src`,
  so scripts fall back to `default-src 'self'`: **no inline `<script>`, no inline event handlers, no `eval`,
  no CDNs, no web fonts**. Inline `style=""` attributes and inline `<svg>` are fine.
- Root Worker `indicogni-site` owns `indicogni.com/*` with static assets; project Workers own more specific
  routes and deploy independently. Root README rule: never create `public/build-your-own/` in the root site.
- The landing page is generated by `build.mjs` from `projects.json` (card: title, tag, url, blurb, meta,
  accent, accentDark). Other sibling cards use the path `/build-your-own/<slug>/` with `tag: "Build"`.

## 1. Information architecture

```
/build-your-own/vmm/                       Landing (course home): pitch, prerequisites, how it works, TOC by part
/build-your-own/vmm/setup/                 "Before you start" (hardware check, toolchain, sign+run smoke test)
/build-your-own/vmm/<part-slug>/<ch-slug>/ Lesson pages (one per chapter)
/build-your-own/vmm/labs/                  Lab index (all in-browser labs, each also embedded in its lesson)
/build-your-own/vmm/labs/<lab-slug>/       Standalone lab page (full-width, shareable)
/build-your-own/vmm/reference/             Memory map, register cheat-sheets, glossary, spec citations
/build-your-own/vmm/about/                 Threat model summary, honesty policy, repo link, changelog
/build-your-own/vmm/404.html               Course-local 404 (Worker asset 404 handling)
```

Chapters are grouped into **Parts**. Numbering is stable and shown (`2.3`). Proposed grouping (lead may
adjust titles; the builder reads parts from `course/chapters.json`, see section 10):

| Part | Title                     | Chapters (working titles)                                                                  |
|------|---------------------------|--------------------------------------------------------------------------------------------|
| 0    | Orientation               | What a VMM is; ARM virtualization model (EL0-EL2, stage-2); setup & signing                |
| 1    | Talking to the hypervisor | HVF FFI; create VM; map guest memory; run a 3-instruction guest; read `ESR_EL2`            |
| 2    | Traps and devices         | MMIO data-abort decoding; PL011 UART; PL031 RTC; memory-map as single source of truth      |
| 3    | A real machine            | GICv3 + vtimer; PSCI over HVC; DTB generation; Image/initramfs loader; **Linux boots**     |
| 4    | virtio                    | virtio-mmio transport; virtqueue rings; virtio-blk; rootfs; hostile-descriptor hardening   |
| 5    | More cores, more guests   | SMP (thread per vCPU); firmware boot; FreeBSD via U-Boot; EDK2                              |
| 6    | Capstone: macOS guest     | Honest investigation: vmapple, AVPBooter, paravirtual devices; what was and was not observed |
| A    | Appendices                | Threat model, testing strategy, productizing (rust-vmm lineage), glossary                  |

Navigation model: three levels only (course > part > chapter). Persistent left sidebar TOC on wide screens,
slide-over drawer on narrow. Every lesson has prev/next. No search in v1 (static site, ~40 pages); a flat
`/build-your-own/vmm/reference/` page plus browser find is enough. Optionally a build-time generated
`search-index.json` + 60-line self-hosted search later.

### Progress model
No accounts, no telemetry (CLAUDE.md). Progress is per-browser in `localStorage` key `vmm-progress-v1`
(set of completed chapter slugs; "completed" is toggled by the learner via a "Mark complete" button, never
inferred). All reads/writes wrapped in try/catch; the site renders identically without it. Landing and
sidebar show check marks and "Continue: 2.3" from this. Copy states plainly "Stored only in this browser."

Required blocks per lesson, in this order (the builder lints presence; missing = build error):
1. **Header**: part/chapter label (mono caps, accent), `h1` (serif), **badges** row, time estimate.
2. **Objectives** box (2-4 bullets, verbs).
3. **Prerequisites** box: prior chapters (links), repo tag/commit to start from, tools. Distinct from objectives.
4. Body with `h2`s, optional `Predict` blocks, code, terminal output, callouts, diagrams, embedded lab.
5. **Checkpoint** box (exactly one): the exact command and exact expected output. For browser-only chapters the
   checkpoint is an in-page self-check (a lab state or quiz) and says so.
6. **Recap** (3 bullets) and **Further reading** (spec section citations, e.g. "ARM ARM D17.2.37 ESR_EL2").
7. **Prev/next** nav and "Mark complete" button.

As built (2026-11-20), the spec follows STYLE.md appendix A rather than the wireframe above:
the header label reads "Chapter 02 · Part I" (no "Part X of N" chip), and the progress bar sits
in the lesson header, named by the "Course progress: chapter NN is K of the M chapters written so far (numbering starts at 00)"
label beside it. The Prerequisites box is the "Concepts you'll need" box; it names the reference
tag (`start_tag`) only when that git tag exists. Items 6 are STYLE's "What now works" list (the
recap, inside the Checkpoint section) and `## Spec hunt` (the further reading); scripts/check-lessons
lints them, so the builder does not lint them twice. "Mark complete" is a toggle button with the
fixed label "Chapter complete" and `aria-pressed`.

### 2.3 Badges (never color alone)

| Badge            | Meaning                                              | Style                                                         |
|------------------|------------------------------------------------------|---------------------------------------------------------------|
| `Needs a Mac`    | Native step on Apple Silicon with Hypervisor.framework | Filled accent chip, text `#FFF` on `--accent`; leading apple-less glyph: a small inline-SVG chip icon |
| `Runs in browser`| Lab/reading works in any browser, no install         | Outlined chip, ink text on card, 1.5px `--muted` border (non-text contrast >= 3:1), leading inline-SVG "window" icon |
| `Mac + browser`  | Both (most lessons)                                  | Two chips side by side                                        |

Chips are `<span class="badge badge--mac">` with visible text and an `<svg aria-hidden="true">` icon, so they
convey meaning by text + shape, not hue. On the curriculum list the badge sits right-aligned; on narrow
screens it wraps under the title.

## 3. Components

All components are plain semantic HTML emitted by the builder; behavior comes from one small
`/build-your-own/vmm/assets/course.js` (<= ~6 KB, no deps). Every component works (degrades to readable
static content) with JS disabled, except labs, which show a `<noscript>` explanation plus a static screenshot-style SVG.

### 3.1 Code block with file path and copy button
```html
<figure class="code" data-lang="rust">
  <figcaption><span class="path">crates/vmm/src/fdt/builder.rs</span>
    <span class="range">lines 12-30</span>
    <button class="copy" type="button" aria-label="Copy code: crates/vmm/src/fdt/builder.rs">Copy</button></figcaption>
  <pre tabindex="0"><code>...</code></pre>
</figure>
```
- Header strip: file path (mono, muted), optional range, copy button right. Path is a plain `<span>` (copy-path
  is not needed). Source of truth: the code is **pulled from the repo by anchor** at build time
  (`// ANCHOR: name`), the path+range are generated, never hand-typed (CLAUDE.md coupling rule).
  Build fails if the anchor is missing; `scripts/check-anchors` is run by the builder.
- `<pre tabindex="0">` so keyboard users can scroll it; `overflow-x: auto`, `max-width: 100%`, `tab-size: 4`.
  No soft wrapping by default (alignment matters in Rust/asm); a "Wrap" toggle is a v2 nicety.
- Copy: `navigator.clipboard.writeText`, fallback to a hidden-textarea `execCommand`. On success button text
  becomes "Copied" for 1.5s and an `aria-live="polite"` region announces "Copied code". Copies code only,
  never line numbers or the `$ ` prompt (line numbers are CSS counters, `user-select: none`).
- Diff-style additions: lines wrapped `<span class="add">` get a left 3px accent bar and a "+" in the gutter
  (not color alone).
- Highlighting: build-time, our own tokenizer for Rust, ARM64 asm, shell, DTS, TOML, C (regex-based, ~150 lines),
  emitting `<span class="tok-k|tok-s|tok-c|tok-n|tok-f">`. No runtime highlighter.

### 3.2 Terminal-output block
Visually distinct from code: it is something you *see*, not something you *type*.
```
 +- Terminal ----------------------------------------------+   <- header chip "Terminal", mono caps muted
 | $ cargo run -- --kernel Image --initrd rootfs.cpio.gz     |   <- prompt line(s): "$ " is user-select:none
 | [    0.000000] Booting Linux on physical CPU 0x0          |   <- output, muted-ink
 | ...                                                       |
 +-----------------------------------------------------------+
```
`<figure class="term"><figcaption>Terminal</figcaption><pre tabindex="0"><code>`; `$` lines get `.cmd`
(full ink, copyable via a Copy button that copies only `.cmd` lines); output lines `.out` (muted ink). Always
labelled "Real output from an M5 Pro, macOS 27.2" **only when captured from a real run** (CLAUDE.md: report
real outputs). Builder supports `:::term source=captures/NN-name.txt` so output is a checked-in capture; every leading
`#` line of the capture is provenance (section 9), rendered as a `captured: ...` footer in small muted mono.

### 3.3 Callouts
`<div class="callout callout--{note|warn|security|mac|why}" role="note">` (not `<aside>`: inside `<main>`
with no `<article>` an aside is a complementary landmark, and a lesson would list five) with a visible mono-caps label and an
inline-SVG icon, left 4px bar. Variants:
- `note` (ink bar), `why` ("Why it works this way", accent bar), `warn` (amber-red, for footguns),
- `security` ("Hostile input": this guest-controlled value must be validated, ties to CLAUDE.md rules),
- `mac` (Mac-specific quirks, e.g. HVF entitlement, W^X, 16KB host pages).
Label text carries meaning; icon is `aria-hidden`. Role is `note` (not a landmark, not a live region).
The stopping point is a plain `<div class="stop">`, and the sidebar is a `<div>` around the
"Course contents" `<nav>`, so no navigation landmark is nested in a complementary one.

### 3.4 Socratic "Predict" block with reveal
Native `<details>` so it works without JS and is keyboard accessible by default.
```html
<details class="predict">
  <summary><span class="predict__label">Predict</span> What happens if the guest writes to 0x0900_0000 before
  you map the UART?</summary>
  <div class="predict__answer">...</div>
</details>
```
UX: the question is always visible; `summary` renders as a button-like row "Reveal answer" (text swapped via
CSS `details[open]`). Optional preceding free-text-less choices (A/B/C) are `<ol>` items; reveal explains
each. Learners are told in the chapter intro: "Commit to a guess first." A page-level "Reveal all / Hide all"
button is provided (JS) for review. Opening is animated by max-height only if `prefers-reduced-motion: no-preference`.
No scoring, no storage of answers.

### 3.5 Checkpoint box
```
+- CHECKPOINT ------------------------------------------ [Needs a Mac] -+
| Run this from the repo root:                                          |
|   $ scripts/test-dtb.sh                               [ Copy ]        |
| You should see:                                                       |
|   PASS dtb: 7 nodes, 2 memory ranges                                  |
| [ ] I saw this output                          (checkbox, local only) |
| Not matching? -> "If it fails" (anchor to troubleshooting list)       |
+-----------------------------------------------------------------------+
```
As built (2026-11-20): the box says "Run this from the repository root:" above the command. It has
no "Not matching?" link: chapters have no per-chapter troubleshooting heading to point at, and
STYLE's "Stuck?" paragraph next to the checkpoint (`scripts/learner hint NN`) does that job in the
prose.
Command from `command:` front-matter field, expected output from `expect:` (both mandatory; builder refuses
a lesson without them). Thicker 2px accent border, accent-tinted background. The checkbox state feeds
progress ("Mark complete" is enabled/emphasized after it) but never gates reading.

### 3.6 Diagrams (inline SVG)
Hand-authored or generated SVG inlined into the HTML by the builder (from `docs/diagrams/*.svg`).
- Each is `<figure><svg role="img" aria-labelledby="t d"><title id="t">..</title><desc id="d">..</desc>`
  plus a visible `<figcaption>`. The `<desc>` is a complete text equivalent (e.g. for the stage-2 walk: lists
  the four levels and the bits consumed at each).
- Colors only via CSS custom properties (`fill: var(--ink)`, `var(--accent)`, `var(--rule)`) so dark mode and
  themes work with zero extra assets. No text baked into raster images. Minimum text 12px at 360px viewport:
  SVGs use `viewBox` + `width:100%; height:auto`. As built (2026-11-20): the builder reads the
  smallest `font-size` in the SVG and its `viewBox` width, and when the text would render below 12px
  in a 290px column (the narrowest lab or prose column at a 360px viewport) it gives the SVG a
  `min-width` class (`.minw-N`, generated into course.css in 40px steps) inside a horizontally
  scrollable `.svg-scroll` wrapper, so text never shrinks below 12px; the wrapper becomes a
  keyboard-focusable named region only when it actually overflows. A stacked variant toggled by a
  media query is still welcome for a diagram that is read often on phones.
- Mermaid sources stay in `docs/diagrams/src/*.mmd` and are pre-rendered offline to sanitized SVG by
  `node course/site/tools/diagrams.mjs` (Node built-ins only; the layout of each diagram is written
  out in that file). The site never loads Mermaid, and a ` ```mermaid ` fence in course Markdown
  is a build error: use `:::diagram src=docs/diagrams/NAME.svg alt="..."`.

### 3.7 Misc
Tables (`.table-wrap{overflow-x:auto}`), bit-field diagrams (HTML table generated from a tiny
`bitfield` directive, which doubles as the static fallback for the ESR lab), keyboard glyphs `<kbd>`,
definition tooltips are NOT used (hover-only); glossary terms link to `/reference/#term` instead.

### 4.3 Typography
- Headings: `--serif` 700. `h1` `clamp(2rem,5vw,3rem)/1.1`; `h2` 1.6rem; `h3` 1.2rem. Letter-spacing -.01em on h1.
- Body: `--sans`, 1.0625rem/1.65 (slightly taller than landing for long reading). Measure `--measure` 44rem
  (~70 characters). Landing uses 1.6; lessons 1.65.
- Mono labels (`.tag`, badges, captions): 600 .72rem, uppercase, .08em tracking, as the landing's `.tag`.
- Code: `--mono` .9rem/1.55 (never below 14px). Inline `code`: `--code-bg` pill, 0.15em padding, 4px radius.
- Backdrop: keep the dotted paper background on landing and course index; lesson body pane is a flat
  `--paper` for reading (the dots stay in the margins only).

### 4.4 Shape and motion
Radius 6px (cards, matches landing). 1px `--rule` borders. Shadows only on hover, same as landing.
Transitions <= 150ms, all disabled under `prefers-reduced-motion: reduce`.

## 5. Responsive rules

- **Gutters**: 16px (`--gutter:1rem`) minimum on viewports <= 640px; 1.5rem (landing value) above.
  `.wrap{max-width:64rem; margin:0 auto; padding:0 var(--gutter)}`.
- **Breakpoints** (mobile-first): base < 640 single column; >= 640 wider gutters, 2-col cards; >= 64rem (1024px)
  three-pane (sidebar | article | on-this-page); between 640 and 1024 two-pane (article + drawer-toggled TOC);
  the right "On this page" rail only appears >= 80rem (1280px).
- **No horizontal page scroll** at any width down to 320px. Enforced by: `img,svg,video,table{max-width:100%}`,
  `pre,.table-wrap,.bitfield{overflow-x:auto}`, `min-width:0` on grid/flex children, `overflow-wrap:anywhere`
  on inline code and long hex constants/URLs. A Playwright-free build check is impossible, so the lead
  verifies manually at 320/375/768/1280 px; the labs' CSS is written to the same rule.
- **Code blocks scroll internally**; `pre` is `max-width:100%`, header strip stays visible (path truncates with
  ellipsis; full path in `title` attribute).
- **Sidebar TOC** collapses to a `<details class="toc-drawer">` "Contents" button at the top of the article
  under 64rem (works without JS).
- **Touch targets** >= 44x44 CSS px for nav, chips that are links, copy and reveal buttons.
- **Labs** are single-column stacked at < 720px: controls above, visualization below, readouts below that;
  wide visualizations scroll inside their own `overflow-x:auto` region or switch to a vertical layout.
- Text zoom to 200% and 400% reflow must keep all content reachable (WCAG 1.4.4, 1.4.10).

## 6. Accessibility

- **Landmarks**: `header`, `nav aria-label="Course contents"`, `main`, `nav aria-label="Previous and next
  chapter"`, `footer`. One `h1`. Skip link ("Skip to lesson") first in DOM, visible on focus.
- **Keyboard**: everything operable by Tab/Shift-Tab/Enter/Space. Predict = native `<details>`. Copy = `<button>`.
  Labs: every control is a native element (`input type=range|number|text`, `button`, `select`); custom widgets
  (grids, trees) use the roving-tabindex + arrow-key pattern with `role` per ARIA APG and a visible instructions
  line. No keyboard traps; Escape closes the TOC drawer and returns focus to its toggle.
- **Focus ring**: reuse landing `:focus-visible{outline:2px solid var(--ink);outline-offset:3px;border-radius:4px}`;
  on dark `--ink` is light so it stays >= 3:1. On accent-filled controls the outline flips to `--paper` with an
  `--ink` offset ring (double ring) so it remains >= 3:1 against both neighbors. Never `outline:none` without
  replacement.
- **Reduced motion**: `@media (prefers-reduced-motion: reduce)` disables transitions, smooth scroll, reveal
  animation, and lab auto-play (labs with animation start paused and offer Play/Step; Step always available).
- **Color independence**: badges, callouts, diff `+` lines, pass/fail text always carry text/shape in addition to
  color. Lab state (changed bit, trapped access) is shown by text and pattern/outline, not hue only.
- **Diagrams**: `role="img"` + `<title>` + `<desc>` + visible caption (section 3.6). Interactive SVG parts are
  not `role="img"`; they are real controls with accessible names.
- **Live regions**: lab readouts that change as you type use `aria-live="polite"` with `aria-atomic="true"` on a
  single summary node (e.g. "EC 0x24: Data abort from lower EL, ISV=1, WnR=write"), throttled to ~300ms.
  Copy confirmation uses one page-level polite region.
- **Language/semantics**: `lang="en"`, headings in order, tables with `<th scope>`, link text meaningful
  ("Next: 3.5 Load the kernel"), no "click here". Abbreviations on first use expanded in prose (`ESR_EL2`).
- **Contrast**: all text >= 4.5:1, UI >= 3:1, verified by `check-contrast` (section 10) in both color schemes.
- **Targets**: >= 44px (also WCAG 2.5.8 24px minimum respected inside dense lab grids, which use 28px cells).
- Zoom not blocked (`viewport` meta without `user-scalable=no`).

## 7. CSP constraints and what they imply

Effective policy (the course Worker ships its own `_headers`, generated by `build.mjs` from its
`CSP` constant; it is stricter than the landing's because the course needs no inline styles):

```
/*
  Strict-Transport-Security: max-age=31536000
  Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self'; font-src 'self'; connect-src 'self'; worker-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'; require-trusted-types-for 'script'; trusted-types 'none'
  X-Content-Type-Options: nosniff
  X-Frame-Options: DENY
  Referrer-Policy: strict-origin-when-cross-origin
  Permissions-Policy: camera=(), microphone=(), geolocation=()
  Cross-Origin-Opener-Policy: same-origin
  Cross-Origin-Resource-Policy: same-origin
/build-your-own/vmm/assets/*
  Cache-Control: public, max-age=31536000, immutable
```
(2026-11-20, as built: `style-src 'self'` without `'unsafe-inline'`, because nothing on the site needs
an inline style: line numbers come from `data-n` attributes, the progress bar is a `<progress>`
element. `img-src` has no `data:`: nothing on the site or in a lab uses a data: URL; add it back,
with a note here, only if a lab needs `canvas.toDataURL()` output in an `<img>`. `browsing-topics` was dropped from Permissions-Policy because current Chrome logs it as an
unrecognized feature on every page. Everything under `assets/` is content-hashed, labs included
(`assets/labs.<hash>/<name>/`), so the immutable rule is safe.)
(`require-trusted-types-for 'script'; trusted-types 'none'` (added 2026-11-20): Trusted Types with no
policy, so the browser refuses every HTML-string and script-URL sink (`innerHTML`, `outerHTML`,
`insertAdjacentHTML`, `script.src`, `new Worker(url)`), even with a literal string. No page and no lab
uses one; the builder's lab lint rejects them first with a clearer message. Browsers without
Trusted Types ignore the two directives. A lab that truly needs a Worker asks the lead: the fix is
a named policy (`trusted-types lab-worker`) that allows only same-origin `assets/labs.*` URLs.)
(`script-src 'self'`, `connect-src 'self'`, `worker-src 'self'` just state what `default-src` already implies; keeping
them explicit documents intent and lets us tighten independently. We do NOT add `'unsafe-inline'` to scripts,
`'unsafe-eval'`, or `wasm-unsafe-eval` unless a lab actually ships WebAssembly; then add only `'wasm-unsafe-eval'`.)

Consequences (hard rules for every author/agent):
1. **No CDNs, no Google Fonts, no analytics, no embeds.** System font stacks only.
2. **No inline `<script>` and no `onclick=`.** All JS in external files under
   `/build-your-own/vmm/assets/*.js` loaded as `<script type="module" src=... defer>`. Initial data for a
   lab is a `<script type="application/json" id="...">` block (data blocks are not executed, so allowed) or a
   fetched `/assets/labs/*.json`.
3. No inline styles either: no `style=""` attribute, no `<style>` element (inline SVG included), no
   `setAttribute("style", ...)`. Use classes and the tokens. Setting a property through the CSSOM
   (`el.style.width = ...`) is not blocked by CSP and is fine in labs.
4. Images: `img-src 'self'`, so inline SVG (preferred) or self-hosted files only.
5. Web Workers OK from same origin files only (`worker-src 'self'`); no blob: workers (not allowed).
6. Clipboard API needs a user gesture and a secure context: fine on https; document fallback for local preview.
7. No `eval`/`new Function` in labs (the DTB/instruction "interpreters" are written as real parsers).
8. Cloudflare may inject nothing: disable Rocket Loader / email obfuscation / auto-minify JS for this
   route (they inject inline script and break CSP); `feedback@indicogni.com` is rendered as plain text + `mailto:` link.
9. `frame-ancestors 'none'`: no iframes of labs; each lab is a first-class page/section.

## 8. In-browser interactive labs

Shared lab shell (`<section class="lab" aria-labelledby>`): title, one-line goal, a "Runs in browser" badge,
controls panel, visualization, **Readout** (plain text live region), "Reset" and "Share state" (state encoded in
`location.hash`, e.g. `#esr=0x93C08045`, so a lab link can be pasted into an issue). Pure ES modules, no
framework; state in a single object, render function `render(state)`; deterministic and unit-testable under
`node --test` (all model logic in `labs/<name>/model.mjs` with no DOM; the same file is imported by the
builder tests and by the browser). Prefer correctness over looks: every lab's model is cross-checked against
fixtures extracted from the real Rust code's unit tests (shared JSON vectors in `course/site/labs/vectors/`).

### 8.1 ESR decoder (`ESR_EL2`)
- Input: hex field (accepts `0x`, underscores), plus "Presets" select: data abort write to UART, instruction
  abort, HVC #0 (PSCI), WFI, sysreg trap, SMC.
- Display: 32-bit register as a segmented bit bar (EC[31:26] | IL[25] | ISS[24:0]); each field a labelled
  segment, hover/focus shows name and bit range; the ISS re-segments according to EC (data abort: ISV, SAS,
  SSE, SRT, SF, AR, FnV, EA, CM, S1PTW, WnR, DFSC).
- Interaction: click/Space on a bit toggles it; changing EC re-labels ISS; invalid/unknown EC shows "reserved".
- Readout: "Data abort from lower EL. Write of 4 bytes from x2. Translation fault, level 3 (DFSC 0b000111)."
- "What the VMM does" panel: the Rust match arm that would handle it, linked to the chapter section.
```
 ESR_EL2  0x9380_0047                                [ Preset v ]  [ Reset ]
 31      26 25 24                                              0
 +--------+--+-------------------------------------------------+
 | EC 0x24|IL|  ISS (data abort layout)                         |
 +--------+--+-------------------------------------------------+
  ISV SAS SSE SRT  SF AR  ...  WnR DFSC
 [1] [10] [0] [00010] [0][0]      [1] [000111]     (each a toggle/number)
 > Data abort from lower EL. Write, 4 bytes (SAS=2), register x2. Translation fault L3.
```

### 8.2 Stage-2 translation walker
- Model: 4KB granule, 40-bit IPA (HVF default is configurable via `hv_vm_config_*`; lab offers 36/40/42-bit),
  levels 0-3 (start level changes with IPA size), a small editable table pool.
- Input: IPA (hex), or click a region in the memory map strip (flash, GIC, UART, virtio, RAM).
- Visualization: IPA split into index fields with bit ranges; four stacked table "cards" (16-entry visible
  window around the index; real tables have 512); a highlighted arrow follows descriptor to descriptor; final
  PA = output address | page offset. Step button advances level by level; Auto-play respects reduced motion.
- Faults: invalid descriptor (translation fault level N), permission (S2AP write to RO), access flag. The
  walker shows exactly the ESR/FAR/HPFAR values hardware would report (links to the ESR lab with state prefilled).
- Edit: toggle a descriptor's valid/AF/S2AP bits and watch the walk fault.
```
 IPA 0x4000_1234 -> [L0 idx 0][L1 idx 1][L2 idx 0][L3 idx 1][off 0x234]
  L0 table @0x...  ->  L1 table  ->  L2 table  ->  L3 table  -> PA 0x...
  +--idx 0--+       +--idx 1--+     +--idx 0--+    +--idx 1--+
  | valid T |  -->  | valid T |-->  | valid T | -> | valid P | => PA = page | 0x234
  [ Step ]  [ Auto ]   Result: OK  S2AP=RW  AF=1
```

### 8.3 MMIO trap simulator
- A mini-guest "program" (5-8 assembly-ish lines, pre-baked, e.g. `str w1,[x0]` to the PL011 data register,
  `ldr w2,[x0,#0x18]` for FR, a write to an unmapped address) executed step by step.
- Panes: guest instructions (current highlighted) | machine memory map (mapped RAM vs unmapped holes)
  | exit log. A store to an unmapped IPA "traps": the sim shows the exit record
  (reason, ESR decoded, FAR/HPFAR -> IPA), then the VMM-side decode steps (ISV, SRT, SAS -> register x1, size 1), the
  device dispatch (address -> PL011 reg), the emulated effect (a character appears in the virtual terminal),
  and the PC advance by 4.
- Teaches the two failure modes: ISV=0 (can't decode: must not guess) and a guest access crossing a device
  boundary. User can edit the target address and register values.
```
 [guest]            [exit]                          [VMM]            [virtual UART]
 > str w1,[x0]  ->  DABT  IPA 0x0900_0000  WnR=1 -> dispatch PL011 -> "H"
   ldr w2,[x0,#0x18]  ...                          read FR = 0x90
 [ Step ] [ Run ] [ Reset ]    Unmapped store to 0x0c00_0000 -> exit: "unhandled MMIO" (log, no crash)
```

### 8.4 virtqueue ring visualizer
- Split-virtqueue (virtio 1.2): descriptor table (N=8 for display), available ring, used ring, with the driver
  (guest) and device (VMM) as two actors, each with its own index.
- Controls: "Driver: add request (chain of 1-3 descriptors; flags NEXT/WRITE)", "Device: process one",
  "Driver: reclaim used", plus a hostile mode with toggles: loop in `next`, `len` beyond table, `addr`
  out-of-bounds, chain longer than cap, index wrap-around (uint16).
- Visualization: three horizontal strips; descriptor chains drawn as linked arrows; `avail.idx`, `used.idx`,
  `last_avail` as moving markers; wrap-around shown with modular indexes. A side list shows the VMM's checks
  firing ("rejected: chain exceeded 16 descriptors", "rejected: loop detected at desc 3") linking to
  the code (`crates/vmm/src/virtio/queue.rs` anchors).
```
 DESC  [0 ][1 ][2 ][3 ][4 ][5 ][6 ][7 ]     flags: N=next W=write
        N>1 N>2  W
 AVAIL idx=3  [0][4][..]         USED idx=1  [0 len=512]
 driver ^avail.idx         device ^last_avail
 [Driver: add]  [Device: process]  [Driver: reclaim]   [ ] hostile mode: loop in next
```

### 8.5 DTB explorer
- Input: a prebuilt sample `.dtb` (fetched from `/assets/labs/sample.dtb`, sha256 shown) or a file the learner
  drops in (read locally with `FileReader`, never uploaded; works under CSP) plus a paste-hex option.
- Views: (a) tree view of nodes/properties; (b) raw bytes hex pane with colored regions (header, memory
  reservation map, structure block tokens FDT_BEGIN_NODE/PROP/END_NODE, strings block); selecting in one view
  highlights in the other; (c) a `reg`/`ranges` interpreter that applies `#address-cells`/`#size-cells` from
  the parent to turn cells into address+size, and flags mismatches (the classic bug in chapter 3.4).
- Parser is hardened exactly as the Rust one: bounds checks, offset overflow, string termination; a
  deliberately corrupt sample shows the parser's error messages.
```
 [ sample.dtb v ]  [ Open file... ]        view: (o) Tree ( ) Bytes ( ) Both
 / (root)                         | 00000000  d0 0d fe ed 00 00 0f a4 ...   <- magic 0xd00dfeed
  |- #address-cells = <2>          |           ^^^^^^^^^^^ header
  |- memory@40000000               | 00000038  00 00 00 01 ...             <- FDT_BEGIN_NODE
  |   reg = <0 0x40000000 0 0x8000000>   -> addr 0x4000_0000, size 128 MiB
```

### 8.6 Boot timeline
- A horizontal, zoomable (keyboard +/-) timeline of the real boot of the learner's own guest: seeded from a
  small JSON of timestamps captured from the real run (`macvmm --trace-json` output; the lab can also load a
  trace file dropped in by the learner). Lanes: vCPU0, vCPU1.., devices (UART, virtio-blk), host threads.
- Events: first instruction, first exit by kind (DABT/HVC/WFI/vtimer), PSCI CPU_ON, GIC init, kernel
  "Booting Linux" line, rootfs mounted, init start. Hover/focus shows details; a filter by exit kind; summary
  counters (exits/second by reason). Includes the reference trace (clearly labelled with machine + commit it was
  captured on) and states "your numbers will differ".
```
 vCPU0  |==run==|D|=run=|H|==========run===========|W|..
 vCPU1  |.........|PSCI ON|====run=====|...
 UART   |         |  "Booting Linux" ... "rootfs" ...|
 0ms        50ms          200ms              1s      <- zoom [ - ][ + ]  filter: [x]DABT [x]HVC [ ]WFI
```

Lab placement: ESR decoder in 1.4; stage-2 walker in 1.2/1.3; MMIO trap in 2.1; DTB explorer in 3.4;
virtqueue visualizer in 4.2/4.4; boot timeline in 3.6 and 5.1. Each lab is embedded in its lesson and also at
`/labs/<slug>/`. A lab never replaces the native work: the checkpoint still requires the real command.

## 9. Content model (what authors write)

Lessons are Markdown in `course/chapters/<part>/<NN-slug>.md` with a small front-matter block
(`---` ... `---`, flat `key: value` and `- list` lines only; parsed by our own parser):

```
---
title: Generate a DTB
part: 3
chapter: 3.4
runs: mac+browser          # mac | browser | mac+browser
minutes: 40
prereqs: [2.4, 3.1]
start_tag: ch-3.3
labs: [dtb-explorer]
command: scripts/test-dtb.sh
expect: PASS dtb: 7 nodes, 2 memory ranges
---
```
Markdown subset (our renderer supports exactly this; anything else is a build error, so there is no
silent drift): ATX headings `#`-`####` (auto ids + anchor links), paragraphs, `*em*`, `**strong**`,
`` `code` ``, links, images (only local, require alt text), ordered/unordered lists (one nesting level),
blockquote, tables (pipe), horizontal rule, fenced code, and **directives** with `:::` fences:

```
:::objectives          :::prereqs         :::predict Question text here
- bullet               ...                (answer body)
:::                    :::                :::
:::callout kind=security title="Hostile input"
:::term source=captures/ch3-4.txt         (checked-in real capture)
:::code anchor=fdt_begin_node file=crates/vmm/src/fdt/builder.rs
:::diagram src=docs/diagrams/stage2-walk.svg alt="..."   (alt becomes <desc>; required)
:::lab dtb-explorer
:::checkpoint             (command/expect come from front matter)
:::
```
Raw HTML in Markdown is escaped (never passed through). That is a security and CSP decision: lessons are
inert text.

**Chapter lessons (authoring kit, 2026-11-20).** The decisions below refine the sketch above for
`course/chapters/**`; `scripts/check-lessons` (`cargo xtask lessons`) enforces them, and
`course/STYLE.md` appendix A is the author-facing version with the exemplar
`course/chapters/I/02-first-exit.md`.

- *Front matter.* Chapters carry exactly `title`, `part` (the part id, e.g. `I`), `chapter` (the
  display number, e.g. `I.1`), `id` (two digits), `runs`, `minutes`, `prereqs` (chapter ids),
  `start_tag` (`ch-NN`, the reference at the end of chapter NN, until the lead fixes the tagging
  convention of open question 4), `labs`, `command: scripts/checkpoint.sh NN` and
  `expect: CHECKPOINT NN PASS`, plus optional `draft`. `title`, `part`, `chapter` and `id` must equal
  `course/chapters.json`. The page `h1` comes from `title`; a chapter body has no `#` heading and
  no heading below `###`.
- *Directive grammar.* A line `:::name args` opens a directive; a bare `:::` closes a container.
  Containers: `objectives`, `prereqs`, `predict`, `callout`, `concepts`. Leaves (one line, no
  closing `:::`): `code`, `term`, `diagram`, `lab`, `checkpoint`, `retrieval`, `stopping-point`.
  Containers do not nest; leaves may sit inside a container. Arguments are `key=value` or
  `key="a b"`. A directive inside a blockquote is not a directive.
- *New directives.* `:::concepts` is the "Concepts you'll need" box, five labelled list groups
  (STYLE appendix A.4); for chapters it replaces `:::prereqs` and is rendered in the Prerequisites
  slot of section 2.2, with `prereqs` and `start_tag` from the front matter. `:::retrieval
  [from=NN,NN]` renders the three-item warm-up from `course/retrieval/NN.md` banks (chapters N-1,
  N-3, N-7 by default, missing ones replaced by the nearest earlier unused chapter; rotate items on
  repeat visits). `:::stopping-point <label>` renders the "good place to stop" marker between two
  sittings.
- *Arguments.* `:::code` needs both `anchor=` and `file=` (repo-relative). `:::term source=` is
  relative to `course/` and names `captures/NN-name.txt` (or a trace, `captures/NN-name.trace.jsonl`,
  rendered as a "Trace file" block whose provenance is the run's `.txt` capture). **All leading
  `#` lines of a capture are provenance, never transcript:** the first (minus its
  `scripts/capture-cmd NN:` prefix) becomes the `captured:` footer of section 3.2, and the author
  instruction "Regenerate with ..." is dropped. Only the first line may wrap: while it has not
  ended in sentence punctuation (`.` `:` `;` `!` `?`), a following `#` line that starts in lower
  case continues it (the older `scripts/capture.sh` header wraps that way). Every later `#` line is
  its own note, listed under the footer and never joined to another, even when it starts in lower
  case ("v.dtb is the file ...", "count=1: ..."). Lines indented after the `#` (`#   set -e`) are
  a verbatim script or listing: consecutive ones render as one `<pre>` block, kept exactly. The rest is the
  transcript (`$ command`, `exit:`, `--- stdout ---`, `--- stderr ---`; an empty section is not
  shown, nor is the blank separator line the capture tool writes before a section marker or a
  `$ ` line). Line ends: `\r\n` and a trailing literal `\x0d` (how the capture tool records a
  guest's carriage return) both end a line; other `\xNN` escapes stay visible, styled as escapes.
  Long lines wrap inside the terminal block. Every character is HTML-escaped: captures hold guest
  output, which is hostile input.
- *Primer front matter.* `title`, `slug`, `kind: primer`, `minutes`, `required_by: [NN]` (must equal
  chapters.json `first_required_by`), `labs` (must match the `:::lab` directives), `runs`, and
  `command`/`expect` when the primer has a `:::checkpoint`. Which chapters use a primer comes only
  from chapters.json (CURRICULUM section 2.1): the header shows "First needed in chapter NN; also
  used in ..." (written chapters only). Objectives live only in the `:::objectives` box. The
  builder rejects `also_used_by:` and `objectives:` in primer front matter so the two cannot drift.
- *Callouts.* Authors write STYLE section 7 blockquotes; the builder maps the label to a variant:
  `> **Security.**` to `security`, `> **Under the hood.**` to `why`, and `> **Try it.**`,
  `> **Aside.**`, `> **Production note.**` to `note`, keeping the label text. `:::callout` stays
  available for the `mac` and `warn` variants. Predict is always `:::predict`: a `> **Predict.**`
  blockquote is a build error, and any other label (not starting with one of the five) is a build
  warning; a one-off label is written `> **Aside: <label>.**`.
- *Required blocks* for a chapter, in order: `:::retrieval` (from chapter 01), `:::concepts`, the
  opening puzzle (prose), `:::objectives`, body sections (at least one `:::predict` from Part I
  on), `## Checkpoint` (holding `:::checkpoint`, at least one `:::term`, then `### What's next`
  and `### Open question`), and `## Spec hunt` (2 or 3 items) as the last section. The
  "What now works" list in the checkpoint section is the page's Recap and `## Spec hunt` its
  Further reading (section 2.2 items 6).
- *Glossary.* The glossary page is built from `course/GLOSSARY.md` (`## Primers` and one
  `## Chapter NN` section per chapter; entries `- **Term** (expansion): definition.`), sorted
  alphabetically; an entry's anchor is its term lowercased with runs of other characters turned
  into `-`.

## 10. Build approach

**Zero-dependency Node build script**, same philosophy as `indicogni-site/build.mjs` (node:fs only, no npm
install, no bundler). Location: `course/site/build.mjs`, run as `node course/site/build.mjs`; output to
`course/site/dist/` (gitignored) laid out as the final URL tree: `dist/_headers` at the asset root and
every page under `dist/build-your-own/vmm/`.

As built (2026-11-20):

- `node course/site/build.mjs` builds and runs the CSP and contrast checks (errors); broken links are
  reported as warnings. `--check` makes links, `#fragments`, missing assets and page size errors too
  (`scripts/check.sh` runs it). `--strict` also fails on warnings, such as a lab that is not built yet.
  `--out DIR` writes elsewhere (the tests build into a temp dir). The build writes into
  `<out>.partial` and renames it over `<out>` only when there are no errors, so a failed build never
  leaves a complete-looking `dist/` behind; the failed tree stays in `dist.partial/` with a
  `BUILD-FAILED.txt` listing the errors.
- Every page's rendered text outside `<pre>`, `<code>` and inline SVG is linted for author notation
  (`PLAN`, `CURRICULUM`, milestone IDs such as M12, risk IDs, `architecture §`/`threat model §`
  references, `[U]`/`[V]`/`[H]` tags, spike references): the same vocabulary scripts/check-lessons
  rejects in chapters, applied to primers, the glossary and the generated pages too. External specs
  cited by section ("UEFI 2.10 §7") are fine.
- `chapters.json` url, slug and file values are validated before they become output paths, and
  `:::code file=` / `:::diagram src=` must stay inside the repository.
- `node course/site/serve.mjs` serves `dist/` on 127.0.0.1:8787 with the `_headers` applied (CSP
  included, caching replaced by `no-store`), `index.html` resolution, trailing-slash redirects and the
  nearest `404.html`, as the Worker does.
- Pages: landing, one page per part, every chapter (a chapter in `chapters.json` with no file yet
  gets a short "planned" page with `noindex`, so links to it resolve), the primers index and every
  primer, the labs index and `/labs/<name>/` for every lab in `chapters.json` plus any lab directory
  present (a lab not built whose chapters are all still planned, a post-v1 lab, gets a short
  "planned" page and its own index section, with no warning), `/glossary/` from `course/GLOSSARY.md`, `/reference/` and `/about/` from
  `src/pages/*.md` (rendered with the same Markdown, so the reference card's memory map and exit
  statuses come from code anchors), `404.html` and `sitemap.xml`.
- Curriculum titles keep their status words in `chapters.json` (`(SHOULD)`, `STRETCH`, `(post-v1)`);
  the site strips them and shows a status badge instead. Primer "covers" text loses author notation
  in `gen-chapters.mjs` (`cleanCovers`).
- Page size limit: 400 KB of HTML per page (the boot-log chapter is about 360 KB uncompressed,
  most of it captured output; on the wire it is a fraction of that).

Recommendation on Markdown: **write our own tiny subset renderer (~300-400 lines) in
`course/site/lib/md.mjs`; do not vendor marked/markdown-it.** Reasons: (1) we need custom directives
(`predict`, `checkpoint`, `code anchor=`) anyway; bolting them onto a general parser costs more than the
parser; (2) a closed subset that errors on unknown syntax guarantees consistent output and gives us
escape-by-default (no raw HTML) which is the right security stance for a CSP-strict site; (3) vendoring ~40-100 KB
of third-party code contradicts the zero-dependency ethos and needs license + update upkeep; (4) the
syntax we need is small and well specified. Mitigation: ship `lib/md.test.mjs` with `node --test` fixtures
covering every construct, plus an "unsupported syntax" negative test. Fall-back if it grows past ~600 lines: vendor
`marked` (MIT) as a single file with a pinned hash and keep only directive handling in our code.

Pipeline:
1. Read `course/chapters.json` (parts, order, slugs, titles, badges, minutes) + all lesson Markdown.
2. Parse front matter; lint required blocks (objectives, prereqs, checkpoint with command and expect, at least
   one `predict` per chapter from Part 1 on, alt text on every image/diagram).
3. Resolve `:::code anchor=` against the real source files; fail on missing anchors (runs
   `scripts/check-anchors` logic in JS). Extract lines, strip anchor comments, record path + line range.
4. Highlight code at build time (own tokenizer); inline SVG diagrams (strip `<script>`, `on*=` attributes,
   `<foreignObject>`; assert `<title>`/`<desc>`).
5. Render pages from `src/templates/*.html` with simple `{{slot}}` replacement (same approach as landing's
   `{{cards}}`); generate sidebar, prev/next, on-this-page TOC, landing curriculum list, sitemap.xml, robots hints,
   `404.html`, per-page `<title>`, canonical URL, OG tags, theme-color metas (copied from landing), `lang`.
6. Emit assets: `assets/course.css` (single file, hand-written; < 25 KB as shipped, after the
   builder strips comments and collapses whitespace and adds the generated `.minw-N` classes;
   `checkSize` fails the build over budget), `assets/course.js`, `assets/labs/*.js`,
   labs data. Content-hash filenames (`course.3f9a1c.css`) for immutable caching.
7. Post-build checks (hard failures): `check-contrast` (parse the tokens in section 4.2, assert ratios),
   `check-links` (all internal hrefs resolve to an emitted file/id), `check-csp` (grep emitted HTML for
   `<script>` without `src`, `on\w+=`, `http://`, and any `https://` resource that isn't a plain outbound `<a>`),
   `check-size` (every page < 400 KB, see the as-built notes above).
8. `node --test 'course/site/**/*.test.mjs'` runs the renderer, tokenizer, lab-model and vector tests.

### 10.1 Deploy: own Cloudflare Worker, route `indicogni.com/build-your-own/vmm*`
Asset directory layout mirrors the URL path, because static assets are served by request path:
`dist/build-your-own/vmm/index.html`, `.../assets/...`, `.../<part>/<ch>/index.html`, etc.

```jsonc
// course/site/wrangler.jsonc
{
  // Project Worker for indicogni.com/build-your-own/vmm/. Static assets only.
  // Most specific route, so Cloudflare picks it before the root site's indicogni.com/*.
  "name": "indicogni-vmm",
  "compatibility_date": "2026-10-01",
  "assets": {
    "directory": "./dist",
    "html_handling": "auto-trailing-slash",
    "not_found_handling": "404-page"
  },
  "routes": [
    { "pattern": "indicogni.com/build-your-own/vmm*", "zone_name": "indicogni.com" }
  ],
  "workers_dev": false
}
```
Notes and caveats for the lead:
- `vmm*` also matches `/build-your-own/vmm-anything`. Acceptable (we own that prefix; no sibling project is
  named `vmm-*`), and it matches what the root README prescribes (`indicogni.com/build-your-own/<slug>*`). If a
  stricter match is wanted, use two routes: `.../vmm` and `.../vmm/*`.
- `404-page` with a nested asset tree serves the nearest `404.html` walking up the path, so ship
  `dist/build-your-own/vmm/404.html` (with the course header) and the root site keeps its own.
- `_headers` lives at the asset root (`dist/_headers`) with paths written as in section 7.
- `html_handling: auto-trailing-slash` makes `/vmm` redirect to `/vmm/` and lets `index.html` files resolve.
  Verify with `wrangler dev` that `/build-your-own/vmm/` (trailing slash) and `/build-your-own/vmm/labs/esr/` resolve.
- Deploy: `cd course/site && node build.mjs && npx wrangler deploy`. Independent of the root site; the root
  site only needs the card below plus a `Sitemap:` line for `public/robots.txt`
  (`Sitemap: https://indicogni.com/build-your-own/vmm/sitemap.xml`).
- The route must be added only after the first successful deploy is previewed (`wrangler dev`) so the live
  path never shows a half-built course. Cloudflare dashboard settings for this route/zone: disable Rocket
  Loader and auto-minify (CSP, section 7 point 8).
- `course/site/dist/` is build output; commit only sources.
