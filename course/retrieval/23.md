# Retrieval 23: macOS guests, the high road: Virtualization.framework

## R1
Q: A Linux guest under Virtualization.framework prints nothing at all, yet the tool reports `VZ guest state: stopped (guest)` and exit 0. The command line was `console=ttyAMA0 macvmm.test=boot`. What ran, and why did you see none of it?
A: Everything ran: the kernel booted, `/init` printed its marker and powered the guest off, which is what `stopped (guest)` means. `ttyAMA0` is the name Linux gives a PL011, and VZ's machine has none; because a console was named, Linux enables only a console of that name; the virtio-console (`hvc0`) registered but was never switched on, so `/init`'s output went nowhere. With `console=hvc0` the same boot prints its log.

## R2
Q: `macvmm` and vz-mac each need one entitlement. Name each, and say at which call a binary signed without it is refused.
A: `macvmm` needs `com.apple.security.hypervisor`; without it, `hv_vm_create` returns `HV_DENIED`. vz-mac needs `com.apple.security.virtualization`; without it, Virtualization.framework rejects the configuration when it is validated, before any machine exists, and vz-mac exits 1. Both are run-time refusals, never link errors.

## R3
Q: Inside a VZ guest, a PCI device reports vendor `0x1af4` and device `0x1042`. What is it?
A: Vendor `0x1af4` is virtio's, and a modern virtio device's PCI ID is `0x1040` plus its virtio type, so this is type 2, a block device (virtio-blk). By the same rule `0x1043` is the console and `0x1044` the entropy source.

## R4
Q: While a VZ guest runs, which process executes its vCPUs and emulates its devices, and how do you show it?
A: Apple's XPC service `com.apple.Virtualization.VirtualMachine`, a separate process started by macOS (its parent is process 1), not the program that configured the VM. `ps -axo pid,ppid,comm` shows both processes; `codesign -d --entitlements -` on the service shows the private entitlements it holds. The configuring program never sees a VM exit.

## R5
Q: The same Alpine kernel boots with RAM at `0x4000_0000` under `macvmm` and at `0x7000_0000` under VZ. Why does the identical binary cope with both?
A: The kernel learns the machine from the device tree it is handed, including the memory node, and each VMM writes its own; an arm64 Image may also be placed anywhere suitably aligned in RAM. The memory map is part of the machine's contract, and the device tree is how that contract reaches the kernel.

## R6
Q: You keep a macOS VM's `disk.img` but recreate its machine identifier and auxiliary storage. Which rule did you break, and where is it written?
A: `VZMacPlatformConfiguration.h` says that when a VM is loaded again, its hardware model, machine identifier and auxiliary storage must be restored to their original values. The disk was installed for that identity and those boot settings, so new ones no longer match it.

## R7
Q: From the configuration class names alone, name two VZ devices that are standard virtio and two that are Apple-specific. Why does the difference matter to a low-level VMM?
A: `VZVirtioBlockDeviceConfiguration` and `VZVirtioConsoleDeviceSerialPortConfiguration` (or the entropy, network or socket classes) are standard virtio, with a public specification. `VZMacGraphicsDeviceConfiguration`, `VZMacKeyboardConfiguration` and `VZMacTrackpadConfiguration` are Apple's. A low-level VMM can implement the first kind from the specification; the second kind has no public specification to implement from.

## R8
Q: A colleague says "Virtualization.framework is a thin wrapper around Hypervisor.framework; we could rewrite it in a weekend." Give two pieces of evidence against it from this chapter.
A: Under the short configuration sits a whole machine generated privately: its own memory map, PCIe bus, interrupt controller, device tree and devices, none of them shown to the client. For macOS it adds a boot ROM, an identity (hardware model, machine identifier, auxiliary storage) tied to Apple's installer, and paravirtual graphics whose guest-facing protocol Apple does not document; and the process that runs it holds private entitlements, such as `com.apple.private.hypervisor`, that no ad-hoc signature can carry.
