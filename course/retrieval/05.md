# Retrieval 05: Two stages, one map: holes in stage 2 on purpose

## R1
Q: A guest stores a byte to `0x0900_0000`, where its UART should be, but your VMM has mapped an ordinary page of RAM there. What does the guest see, and what does your VMM see?
A: The guest sees a store that worked: the byte sits in RAM, and a load from the same address returns it. Nothing is printed. Your VMM sees nothing at all: a mapped address never causes a VM exit, so the VMM never learns the store happened. A device register needs a stage-2 hole, so each access stops the guest.

## R2
Q: With its MMU on, a guest stores to the virtual address `0x0b10_0000`, which its own page tables translate to `0x0b00_0000`. Nothing is mapped at `0x0b00_0000` in stage 2. Which address does the VM exit report, and why that one?
A: `0x0b00_0000`, the IPA. Stage 2 is the stage that failed, and by then the hardware had already translated the virtual address through the guest's stage 1, so it records the IPA's page number (in `HPFAR_EL2`, with the offset from `FAR_EL2`) and the VMM never has to read the guest's tables. The virtual address means something only inside the guest's current address space.

## R3
Q: A data-abort exit has the syndrome `0x93890046`. Is it a load or a store, how wide, and what kind of fault?
A: The class is `0x93890046 >> 26 = 0x24`, a data abort from the guest. Bit 6 (WnR) is 1, so a write. Bits 23:22 (SAS) are `0b10`, so `1 << 2 = 4` bytes. The low six bits (DFSC) are `0x06`: a translation fault at level 2, meaning stage 2 found no entry for the address.

## R4
Q: Your machine has 512 MiB of RAM from `0x4000_0000`, so RAM ends at `0x6000_0000`. How many IPA bits does the address space need, and what does `ipa_bits_needed(0x6000_0000)` return?
A: 31 bits would be enough: `1 << 30 = 0x4000_0000` is too small, `1 << 31 = 0x8000_0000` covers `0x6000_0000`. The function returns 36, because it never asks for less than HVF's default size, so a small machine gets the same VM it would get without the setting.

## R5
Q: Where does virtio slot 5 live, and which INTID does it use?
A: At `0x0a00_0000 + 5 × 0x200 = 0x0a00_0a00`, with INTID `48 + 5 = 53`. QEMU's `virt` board wires slot *i* to shared interrupt line (SPI) `16 + i`, and SPIs are numbered from INTID 32, so slot *i* is INTID `32 + 16 + i`.

## R6
Q: A layout puts a trapped device window of `0x200` bytes at `0x0a00_0200` and RAM at `0x4000_0000`. Which of the two must be 16 KiB-aligned, and why only that one?
A: Only RAM. A mapped region goes through `hv_vm_map`, which works in whole 16 KiB host pages. A trapped window is never mapped: it is the absence of a mapping, so it can have any size and alignment.

## R7
Q: A guest stores to `0x10_0000_0000` (`1 << 36`) in a VM with a 36-bit IPA space. What does the exit's DFSC say?
A: `0x04`: a translation fault at level 0. The address is outside the input range of the stage-2 tables, so the hardware does not look it up at all. We checked this on a real Mac; it is not an address-size fault.

## R8
Q: Your VMM hard-codes a 31-bit IPA space and you start a guest with `--mem 2G`. What happens, and before or after the guest runs its first instruction?
A: Before: RAM from `0x4000_0000` would end at `0xC000_0000`, past `1 << 31 = 0x8000_0000`, so `hv_vm_map` refuses the RAM with `HV_BAD_ARGUMENT` and the VM never starts. The width of the map has to cover the layout, which is what `ipa_bits_needed` computes.

## R9
Q: Without a second translation stage, how would a VMM keep a guest from reaching host memory it does not own, and what would it cost?
A: With shadow page tables: the VMM keeps its own tables that map guest virtual addresses straight to host memory, write-protects the guest's tables, and updates the shadow copy on every trapped write. Every guest page-table write becomes a VM exit, which is why hardware added stage 2.
