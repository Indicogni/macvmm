# Retrieval 06: vCPU state: registers, PSTATE and reset

## R1
Q: Build the PSTATE value for "EL1, using EL1's own stack pointer, with debug, SError, IRQ and FIQ all masked". Show the three parts you add.
A: The four mask bits D, A, I, F are bits 9 to 6: `0x200 + 0x100 + 0x80 + 0x40 = 0x3c0`. EL1 in bits 3 to 2 is `1 << 2 = 0x4`. The stack-pointer select bit 0 set means `SP_EL1`: `0x1`. Together `0x3c5`, the mode EL1h.

## R2
Q: A dump shows `cpsr=0x3c9`. Which level and stack pointer is that, and what does HVF do if you start a vCPU there without offering EL2 to the guest?
A: `M[3:0] = 0b1001`: EL2 (bits 3 to 2 = `0b10`) with its own stack pointer, EL2h, all four masks set. Without EL2 offered, the guest cannot be in that mode, and `hv_vcpu_run` refuses with `HV_ILLEGAL_GUEST_STATE` before the guest runs a single instruction: no VM exit at all.

## R3
Q: A guest dies with `pc=0x200`, `VBAR_EL1=0x0`, `ELR_EL1=0x40081094` and `ESR_EL1=0x96000021`. What went wrong first, and where?
A: The PC is `VBAR_EL1 + 0x200`, a vector entry, so the guest took an exception at EL1 first and its handler (which does not exist) faulted on the fetch. The first fault is in `ESR_EL1`: class `0x25`, a data abort at the same level, with fault status `0x21`, an alignment fault, caused by the load at `0x40081094`.

## R4
Q: The guest runs `svc #0x4d` at EL1 with a vector table of its own installed. How many VM exits does that `svc` cause, and why?
A: None. An `svc` from EL1 is routed to EL1, so the guest's own vector table handles it (`ESR_EL1 = 0x5600004d`, class `0x15`). Only exceptions routed to EL2 and forwarded by HVF reach the VMM.

## R5
Q: What value does the VMM give vCPU 0's `MPIDR_EL1`, and why is the top bit set when the CPU number is 0?
A: `0x8000_0000`. The affinity fields that number the CPU (`Aff0`, `Aff1`, …) are all 0 for the first CPU, and bit 31 is defined as always 1 (RES1) by the architecture.

## R6
Q: Reset clears three bits of `SCTLR_EL1`. Which, and why does a kernel want them clear at entry?
A: M (bit 0, stage-1 address translation), C (bit 2, data caching) and I (bit 12, instruction caching). A kernel turns translation and caches on itself, in an order it controls; it cannot trust translation or cache state left behind by whatever ran before it.

## R7
Q: You start a test guest in EL1t (`0x3c4`) instead of EL1h. Its start code sets `sp` and prints fine, but the first exception it takes never returns. Which register explains it?
A: `SP_EL1`. In EL1t, the start code's `sp` is `SP_EL0`, so `SP_EL1` keeps its reset value 0. Taking an exception to EL1 always switches to `SP_EL1`, so the handler's first store goes below address 0, faults, and re-enters the same handler forever, inside the guest.

## R8
Q: A guest asks the platform for a system reset. Is that the same thing as the reset state `Vcpu::reset` creates?
A: No. The reset state is the set of register values a CPU has at power-on, which `Vcpu::reset` recreates for one vCPU. A system reset is a request, made through PSCI (chapter 08), to restart the whole machine; it ends with every vCPU back in its reset state.
