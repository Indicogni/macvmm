# Retrieval 09: A device is a state machine: the bus, PL011 and PL031

## R1
Q: A guest reads the PL011's flag register `FR` and gets `0x90`. May it write a byte to `DR` now, and is there a byte for it to read?
A: `0x90` is bit 7 (TXFE, transmit FIFO empty) plus bit 4 (RXFE, receive FIFO empty). It may send: the transmit side is empty, so TXFF (full) is clear. There is nothing to read: RXFE says the receive FIFO is empty, and a `DR` read now would return 0.

## R2
Q: The host typed one letter, `a` (`0x61`), and the guest reads the PL011's `DR` twice in a row. What does each read return, and why do they differ?
A: `0x61`, then 0. A `DR` read pops the receive FIFO: the first read removes the byte it returns, so the second finds the FIFO empty. A register whose read changes the device cannot be modelled as a stored value.

## R3
Q: `IMSC` is 0 when a byte arrives at the PL011. What do `RIS` and `MIS` read, and is the interrupt line high or low?
A: `RIS` has the receive bit (bit 4, `0x10`) set, and in our model the receive-timeout bit (bit 6) too: the device remembers that it wants attention. `MIS` is `RIS & IMSC` = 0 and the line stays low: the mask says not to say so. Setting `IMSC` bit 4 later raises the line at once, because the condition still holds.

## R4
Q: The bus holds the PL011 at `0x0900_0000` with size `0x1000`. What does `Bus::insert` answer for a device at `0x0900_0ff8` with size `0x10`, and for one at `0x0900_1000` with size `0x1000`?
A: The first is refused with `BusError::Overlap`: its first eight bytes fall inside the PL011's window. The second is accepted: it starts exactly where the PL011 ends, so the two windows are adjacent, not overlapping.

## R5
Q: A guest makes a 4-byte read at `0x0900_0ffe`, two bytes below the end of the PL011's window. Which register does the PL011 see?
A: None. The access starts inside the window but runs past its end, so the bus answers `BusError::Straddle` and the VMM treats it like an access to no device at all. No device ever sees a partial access, so no device has to reason about one.

## R6
Q: The guest stops reading its UART, and you keep typing. Why must the stdin thread's push into `SerialInput` drop bytes instead of waiting for room?
A: The same thread reads Ctrl-A x. If it blocked waiting for the guest, a guest that never reads would also stop the host from seeing the quit keys, and the user would lose every in-band way out. So `SerialInput` holds 4 KiB, drops and counts the rest, and the thread goes straight back to `read`.

## R7
Q: You press Ctrl-A x in a running `macvmm`, and in another run you send it SIGTERM. Which exit code do you get each time, and why that number?
A: 130 both times. 130 is the shell's code for "ended by SIGINT" (128 + 2), and macvmm uses it for every user quit. A program killed by SIGTERM would report 143, but macvmm catches the signal, stops the VM cleanly and chooses its own code.

## R8
Q: A guest prints the four bytes `ESC [ 6 n` to the UART. What would your terminal do with them, and what does macvmm's output filter do?
A: They ask the terminal for the cursor position, and the terminal *types* its answer into the program's input, where the guest, or after macvmm exits your shell, would read it. The default (`safe`) filter drops the sequence, so it never reaches the terminal.

## R9
Q: Why does the PL031 read the host's wall clock on every `RTCDR` access instead of storing the boot time and adding the time elapsed since?
A: A monotonic clock such as Rust's `Instant` stops while the Mac sleeps, so "boot time + elapsed" would fall behind the real date by every hour of sleep. Reading the wall clock each time stays right; the reference also never lets the value go backwards if the host clock is stepped back.

## R10
Q: A driver makes an 8-byte read of the PL011's `FR` (offset `0x18`), then a 1-byte read of the same register. What does each return?
A: The 8-byte read returns 0, with a rate-limited warning: the PL011's registers are at most 32 bits wide, so that access names no register and is read-as-zero, write-ignored. The 1-byte read returns the low byte of `FR`, `0x90` after reset: a narrow access at a register's offset reaches the register.
