# Retrieval 08: System registers, injection, hypercalls and PSCI

## R1
Q: A VM exit reports the syndrome `0x62280520`. Which instruction stopped the guest, and on which register?
A: `0x62280520 >> 26 = 0x18`: a trapped `msr` or `mrs`. The ISS `0x280520` gives Op0 2, Op2 4, Op1 0, CRn 1, Rt 9, CRm 0, direction 0: an `msr` (a write) from `x9` to the register at (2, 0, 1, 0, 4), which is `OSLAR_EL1`.

## R2
Q: The guest is at EL1h with `VBAR_EL1 = 0x40080800` when your VMM injects an UNDEF. Where does the guest's PC go, and what is in `ESR_EL1`?
A: To `0x40080800 + 0x200 = 0x40080a00`, the synchronous entry for "current EL, using `SP_EL1`". `ESR_EL1` holds `0x02000000`: exception class 0 ("unknown reason"), IL 1, ISS 0.

## R3
Q: After injecting an UNDEF for an `mrs` at `0x4008126c`, should your VMM also add 4 to the PC it saved in `ELR_EL1`?
A: No. An UNDEF is a fault, so `ELR_EL1` must hold the address of the `mrs` itself, as real hardware would leave it. Whether to skip the instruction is the guest handler's decision, not the VMM's.

## R4
Q: A guest that ran in EL0 makes an access your VMM must answer with an UNDEF. Which vector table offset does the injection use, and why not `0x200`?
A: `0x400`: the exception comes from a lower level (EL0) running 64-bit code. `0x200` is for an exception taken at the same level, EL1, using `SP_EL1`.

## R5
Q: The guest calls `hvc #0` with `x0 = 0x84000008`. What does it ask for, and what does `macvmm` return to the shell?
A: `0x84000008` is a fast, 32-bit-convention call of owner 4 (standard secure service), function 8: PSCI `SYSTEM_OFF`. The VM stops and `macvmm` exits with code 0.

## R6
Q: A guest calls PSCI `SYSTEM_RESET`, and `macvmm` was started with `--on-reset exit`. What happens, and what changes with the default setting?
A: The process ends with exit code 4. With the default `--on-reset reboot`, the VMM rebuilds the machine from the same inputs and boots it again, unless the guest resets too often in a short window, which ends with exit code 3.

## R7
Q: Your VMM handles a PSCI call that arrived through `smc #0` at `0x40081378`. Where must the guest resume?
A: At `0x4008137c`. An `smc` is intercepted before it executes, so the saved PC points at it, and the VMM advances it by 4. After an `hvc`, the PC already points past the call.

## R8
Q: The guest reads a system register that no row of your policy table names. What does the reference VMM do, and why that default?
A: It injects an UNDEF, with a rate-limited warning naming the register. A real CPU raises UNDEFINED for a register it does not have; answering 0 would let the guest believe something false without anyone noticing.

## R9
Q: The guest calls `hvc #0` with `x0 = 0x84000099`. What comes back, and in which register?
A: `NOT_SUPPORTED`, -1 (all ones), in `x0`, with a warning on the VMM's standard error. An unknown function ID is never silent and never a crash.
