# Retrieval 11: Getting the CPU back: the timer and a bare interrupt

## R1
Q: A guest reads `CNTV_CTL_EL0` and gets `0b101`. Is its timer raising its interrupt output right now? What about `0b111`?
A: `0b101` is `ENABLE` (bit 0) and `ISTATUS` (bit 2) with `IMASK` (bit 1) clear: enabled, not masked, count reached, so yes, the output is up. `0b111` has `IMASK` set as well: the condition still holds, but the interrupt is masked at the timer, so the output is down.

## R2
Q: The counter runs at 24 MHz. A guest wants an alarm 250 ms from now and reads `CNTVCT_EL0 = 1,000,000`. What does it write to `CNTV_CVAL_EL0`?
A: 250 ms is a quarter of 24,000,000 ticks, 6,000,000 ticks, so it writes 7,000,000. The compare value is an absolute count, not a delay.

## R3
Q: A VMM sets the vtimer offset to the host's tick count when the VM boots. Ten minutes later the guest is paused for an hour and then resumed without changing anything. What does the guest's counter show on resume, and what offset would make it continue where it stopped?
A: It jumps forward by an hour of ticks, because `CNTVCT = mach_absolute_time() - offset` and the host kept counting. To resume where it stopped, recompute the offset as the host count now minus the count the guest last saw (`restore_offset(now, saved)`); then the counter continues from `saved`.

## R4
Q: With no interrupt controller, your VMM got a `VTIMER_ACTIVATED` exit. Before the next entry the guest's `CNTV_CTL_EL0` still reads `ENABLE = 1, IMASK = 0, ISTATUS = 1`. Do you unmask the vtimer? What do you do instead?
A: No: the level line is still high, so an unmasked vtimer would exit again at once, before the guest could handle anything (a real Mac shows millions of VTIMER exits). Keep it masked and set the vCPU's IRQ pending for this run with `hv_vcpu_set_pending_interrupt`; unmask only once `CNTV_CTL_EL0` shows the timer quiet.

## R5
Q: A guest's timer fires while the guest has `PSTATE.I` set and is busy in a loop for another 200 ms. When does its IRQ handler run, and is the interrupt lost meanwhile?
A: When the guest clears the mask, about 200 ms later. It is not lost: the timer's output is a level, still high, and the VMM keeps the IRQ pending before every entry, so the interrupt waits as state until the CPU listens.

## R6
Q: A WFI exit arrives with the PC at `0x40081188`. Where must the PC point when you resume the guest, and is it a bug if you resume at once without sleeping?
A: At `0x4008118c`: a trapped `WFI` leaves the PC at the instruction, so the VMM adds 4. Resuming at once is not a bug, because `WFI` is allowed to end early; it only costs a busy host core while the guest is idle.

## R7
Q: Your `--stats` line reads `vtimer 1, wfx 9435272` after a 10-second timeout, and the guest printed one interval. What did your VMM most likely forget?
A: To unmask the vtimer once the guest silenced it. The framework masks the vtimer at the first VTIMER exit; if it stays masked, no further VTIMER exit comes, the WFI handler finds the deadline already past and wakes at once, and guest and VMM loop on WFI exits.

## R8
Q: A tick handled with no interrupt controller costs three exits. Your exit costs 1.43 µs. What host CPU do the exits alone cost at 10 Hz and at 250 Hz, and why was the measured 250 Hz cost (23% of a core) so much higher?
A: 30 exits per second is about 43 µs per second (0.004%); 750 per second would be about 1 ms per second (0.1%). The measured cost was the guest's own time: after each tick it re-took the stale pending IRQ for over a millisecond until the kick let the VMM drop the line, because the VMM cannot see the guest finish with the interrupt. That lost time also slowed the guest to about 150 ticks per second.

## R9
Q: A key press is signalled as a short pulse while the CPU has IRQs masked. With no latch, what happens to it? Which PL011 register is the latch?
A: It is lost: an edge is an event, and nobody was listening. The PL011's `RIS` latches it (it remembers that a byte arrived until the guest clears it), and `MIS`, `RIS` combined with the mask `IMSC`, turns that memory into a level output.
